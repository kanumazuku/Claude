# AI合議室

Claude、GPT、Gemini、ローカルLLMなど、さまざまなAIが議論しながら、ユーザーのプロンプトへの回答を共同で作り、修正していくWebアプリです。

**参加者のAIは全員が対等です。** リーダーや編集長はおらず、誰が初稿を書くかはくじ引きで決まり、回答の完成には全員の承認が必要です。

## 回答ができるまで

1. **方針の議論**：全員が順に、プロンプトの解釈、回答に含めるべき内容、構成案、注意点を出し合います。
2. **初稿**：くじ引きで選ばれたAIが、全員の意見を踏まえて初稿（第1版）を書きます。
3. **修正ラウンド**：全員が順番に原稿を読み、【意見】を述べたうえで【判断】として「承認」か「修正」を選びます。修正する場合は【修正版】として全文を書き直し、それが新しい版になります。
4. **完成**：全員が同じ版を承認した時点で完成です。最大ラウンドまでに全員の承認がそろわなかった場合は、最も多くの承認を得た版（同数なら新しい版）を回答とします。

画面の左には議論の流れが、右には「共同原稿」がリアルタイムで表示されます。共同原稿では、版ごとの内容と承認状況を切り替えて確認でき、各修正の変更点（追加・削除した行）も見られます。完成した回答はコピー・保存でき、議論全体と版の履歴は議事録（Markdown）として保存できます。

## 対等にするためのしくみ

| しくみ | 内容 |
|---|---|
| 役割の区別をなくす | 全員が同じ指示文を受け取ります。違うのは名前と観点・個性だけです。 |
| 初稿の担当はくじ引き | 誰が初稿を書くかを、くじ引きで決めます。書けなかった場合は、くじを引き直します。 |
| 初稿の担当者は最後に確認 | 初稿を書いたAIは修正ラウンドの最後に回り、ほかの全員が先に原稿を見ます。 |
| 発言順の輪番 | 修正ラウンドごとに発言順を1人ずつずらします。 |
| 完成には全員の承認が必要 | 修正版が出ると承認はやり直しになり、新しい版を全員が改めて承認するまで完成しません。 |
| 最後に書いた人を優遇しない | 承認がそろわないまま終わった場合も、最後に修正した版ではなく、最も多くの承認を得た版を採用します。 |

その版をすでに承認している参加者（その版を作った本人を含む）の番は、同じ版を見直す必要がないため省略します。この規則は全員に同じように適用されます。

## 使えるAI

| AI | 必要なもの | 既定のモデル |
|---|---|---|
| Claude（Anthropic） | `ANTHROPIC_API_KEY` | `claude-opus-5-5` |
| GPT（OpenAI） | `OPENAI_API_KEY` | `gpt-5.5` |
| Gemini（Google） | `GEMINI_API_KEY` | `gemini-3.8-flash` |
| ローカルLLM（Ollama） | Ollamaを起動しておく | `gemma3` |
| デモ | 不要 | 定型文を返すだけのAI |

参加者ごとに、使うAIとモデルを画面で選べます。APIキーが設定されているAIは自動で検出され、参加者に順番に割り当てられます。キーが1つもなくても、デモAIで流れを試せます。

## はじめかた

Python 3.10以上が必要です。

```bash
python -m venv .venv
source .venv/bin/activate          # Windowsでは .venv\Scripts\activate
pip install -e .

cp .env.example .env               # 使いたいAIのAPIキーを書き込む
python -m ai_council
```

ブラウザーで http://127.0.0.1:8000 を開きます。

### 設定（.env）

APIキーのほかに、次の項目を変更できます。詳しくは`.env.example`を見てください。

| 項目 | 内容 | 既定値 |
|---|---|---|
| `COUNCIL_CLAUDE_MODEL` など | 各AIの既定のモデル | 上の表のとおり |
| `COUNCIL_CLAUDE_EFFORT` | Claudeの思考の深さ（`low`〜`max`） | `medium` |
| `OLLAMA_HOST` | OllamaのURL | `http://localhost:11434` |
| `COUNCIL_MOCK_DELAY` | デモAIが文字を流す間隔（秒） | `0.015` |
| `COUNCIL_HOST`、`COUNCIL_PORT` | サーバーの待ち受け先 | `127.0.0.1`、`8000` |

サーバーは既定で自分のPCからしか接続できない`127.0.0.1`で起動します。APIキーを使って費用が発生するため、外部に公開する場合は認証を追加してください。

## 費用の目安

参加者をN人、修正ラウンドの最大数をRとすると、AIの呼び出しは次のとおりです。

- 方針の議論：N回
- 初稿：1回
- 修正ラウンド：最大でR×N回。全員の承認がそろった時点で終わり、すでに承認している参加者の番は省略するので、多くの場合はこれより少なくなります。

参加者3人、修正ラウンド2回の場合は、最大で10回です。

修正版を出すAIは原稿の全文を書き直すため、長い回答ほど出力が増えます。議論の記録には意見だけを残し、古い版の全文は渡さないようにして、入力が膨らみすぎないようにしています。

## 構成

```
ai_council/
├── main.py              Webサーバー（FastAPI）。画面の配信と、合議のリアルタイム配信（SSE）
├── council.py           合議エンジン。方針の議論、くじ引き、修正ラウンド、承認の管理、版の差分
├── prompts.py           AIへの指示文。議論や修正の進め方を変えたいときはここを編集
├── schemas.py           画面から受け取る合議の設定
├── config.py            .envの読み込み
├── providers/
│   ├── base.py          AI共通のインターフェース
│   ├── claude_provider.py
│   ├── openai_provider.py
│   ├── gemini_provider.py
│   ├── ollama_provider.py
│   └── mock_provider.py デモAI
└── static/              画面（HTML、CSS、JavaScript）
tests/                   テスト（APIキー不要）
```

### 新しいAIを追加するには

1. `providers/`に`Provider`を継承したクラスを作り、`status()`と`stream()`を実装します。
2. `providers/__init__.py`の`build_registry()`に登録します。
3. 画面の色を付けたい場合は、`static/app.js`の`PROVIDER_COLORS`と`static/style.css`に追加します。

## Claudeの呼び出しについて

- 公式SDK `anthropic` を使い、ストリーミングで発言を受け取ります。
- Claude Opus 5.5は常に思考してから発言します。思考の深さは`COUNCIL_CLAUDE_EFFORT`で調整できます。
- 対応モデル（Opus 5.5など）では、安全分類器が発言を辞退したときに別のモデルが引き継ぐ「サーバー側フォールバック」（ベータ機能、`fallbacks: "default"`）を有効にしています。不要な場合は`providers/claude_provider.py`の`_FALLBACK_MODELS`を空にしてください。

## テスト

```bash
pip install -e ".[dev]"

```
